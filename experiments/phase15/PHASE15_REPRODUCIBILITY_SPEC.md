# Phase 15 Reproducibility Spec

## 1. Randomization and Stochastic Control

To ensure differences in outcome are attributable solely to the Phase 14 architecture rather than stochastic variation:
- **LLM Settings:** Temperature must be set to `0.0`. `top_p` and `top_k` set to deterministic defaults.
- **Random Seeds:** A fixed integer seed (e.g., `SEED=42`) must be used for any necessary pseudo-random processes (e.g., tie-breaking in RRF sorting).
- **Corpus State:** The document corpus and Neo4j graph state must be frozen. No documents may be added, updated, or deleted during the experiment.

## 2. Order and Execution Independence

- Each experimental unit will be processed by the Baseline system and the Hardened system independently.
- To prevent caching or memory leakage, the orchestrator and security contexts must be completely re-instantiated for every run.
- Order effects are neutralized because the systems run in completely isolated Python processes/test fixtures.

## 3. Contamination and Leakage Prevention

- **Baseline Contamination:** The Baseline system must not have access to the `SecurityDecision` outputs or `TrustFactorScores` generated by the Hardened system.
- **Data Leakage:** The 200 cases selected for Phase 15 must NOT have been used to tune the Trust Scorer thresholds or Prompt Injection regex patterns during Phase 1–14 development.
- **Result Leakage:** Ground truth labels must be generated based on external pharmacological reference, independently of the LLM outputs produced during the experiment.
