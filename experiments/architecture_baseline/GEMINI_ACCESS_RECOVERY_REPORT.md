## 3. Root Cause Analysis

The configured project is receiving a zero quota for `gemini-3.1-pro-preview` on the Free tier. Google's current documentation states that preview models may have more restrictive limits and that Tier 1 is obtained by setting up and linking an active billing account. The observed zero-quota condition is therefore consistent with a usage-tier/billing provisioning blocker.

**Source:** [Google AI for Developers — Rate Limits](https://ai.google.dev/gemini-api/docs/rate-limits)

---

## 4. Quota Semantics & API Keys

```text
QUOTA_SCOPE = PROJECT
```

Google documents Gemini rate limits as project-level rather than simply API-key-level. Therefore, creating another API key in the SAME project is not expected to create an independent quota pool. Do not create unnecessary keys.

---

## 5. Billing Remediation Path

Google currently documents that moving from the Free tier to the Paid/Tier 1 tier requires setting up and linking an active billing account. Accounts placed on the Prepay flow must add the applicable prepaid credit; Google currently documents a \$5 minimum for that flow.

Free → Tier 1 typically takes effect instantly, but timing is not an absolute guarantee.

*Note on status:*
- **BILLING_ACCOUNT_LINKED**: Unverified
- **PREPAY_SETUP**: Unverified
- **CREDIT_BALANCE**: Unverified
- **USAGE_TIER**: Free tier (inferred from `limit: 0`)
